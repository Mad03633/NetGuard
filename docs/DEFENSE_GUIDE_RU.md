# Защита NetGuard Cognitive DSS

Порядок по заданию: PDF — 5 минут, живой Streamlit — 2 минуты, ответы — 3 минуты. Показать приложение нужно на своём компьютере; скриншоты не заменяют запуск. Фактический состав команды проверьте по своим данным: исходные README и demo содержали разные списки, поэтому титул PDF использует «NetGuard project team».

## Подготовка

1. Запустите `RUN_WINDOWS.cmd`, откройте `http://localhost:8501`. Для нового компьютера выполните установку из README на Python 3.10–3.12.
2. Выберите «Демонстрационные сценарии» → «Неоднозначный HTTP», число выбранных сигналов = 5, веса 60/25/15. В свежей базе риск 0.6542, рекомендация «Предложение карантина». Если уже вводили feedback, состояние закономерно отличается. Для чистого репетиционного запуска задайте `NETGUARD_RUNTIME_DIR=runtime_defense` в отдельном окне PowerShell до запуска; старую базу удалять не нужно.
3. Откройте PDF. До защиты проверьте кнопки «Действие» и «Обучение». Изолированная демонстрация «Обучение» работает независимо от накопленной памяти.
4. Подготовьте `data/demo_flows.csv` для загрузки. Пять строк являются синтетическими сценариями. NSL-KDD — отдельный существующий набор исторических записей, не захват сетевых пакетов.

## Ответы на типовые вопросы

**Где настоящее обучение?** В `cognitive/learning.py`: подтверждённая метка связывается с реально сохранённым report_id и сохраняется в SQLite. `Memory.retrieve` вычисляет posterior Beta по подтверждённым меткам. `reasoning.py` использует его на следующих проходах. Дедупликация обеспечивается первичным ключом feedback.report_id. Это online-обучение статистики паттернов, не дообучение Random Forest.

**Почему это память, а не просто лог?** Извлечённые подтверждённые исходы меняют риск и значения критериев. Неподтверждённые предыдущие предсказания не становятся метками сами собой. Память переживает перезапуск, что проверяется отдельным тестом.

**Почему WSM корректен для benefit/cost?** Каждая величина имеет заранее объявленные границы 0–100. Benefit делится на 100, cost преобразуется как 1−x/100. После нормализации весов сумма вес×полезность максимизируется. В тесте есть ручной расчёт 0.75, 0.50, 0.375. Нули, отрицательные/нечисловые/бесконечные значения проверяются до расчёта.

**Зачем фиксированные границы вместо min-max по альтернативам?** Одинаковое относительное изменение всех Protection не должно исчезать после нормализации. Фиксированные границы сохраняют влияние абсолютного риска. Они требуют обоснования самих шкал; здесь это явные учебные предположения.

**Почему top-k влияет на решение?** Риск суммирует только выбранные salience-вклады с неизменными коэффициентами. Меньший top-k исключает остальные вклады. Он не просто меняет отображаемую таблицу.

**Что делает «Действие» с внешним миром?** Пишет реальный локальный JSON и запись аудита. Локальный файл является выходным артефактом действия по заданию. «Предложение карантина» — название альтернативы, а не выполненная сетевая блокировка.

**Что сохранено от NetGuard?** Данные, ноутбуки, исследовательские материалы, старый web frontend и API. Вместо отсутствующих бинарных моделей (Git LFS pointers) отдельно обучен RF с seed 42; оригинальные указатели сохранены. Не заявляйте воспроизведение старых результатов GNN/Transformer/TabPFN.

**Доказывает ли снижение риска улучшение качества?** Нет. Оно доказывает изменение поведения на заданных подтверждённых исходах. Для оценки полезности нужно независимое исследование на новых данных с качественными метками и ценой ошибок. Риск DSS — эвристический индекс, не калиброванная вероятность.

**Какие ограничения у WSM и feedback?** WSM допускает компенсацию плохого критерия хорошим; строгих security-ограничений нет. Feedback может содержать ошибки, а объединение protocol/service грубое. Влияние feedback ограничено, но это не полная защита от poisoning.
